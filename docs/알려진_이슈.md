# 알려진 이슈 (Known Issues)

현재(#5 시점) 파악된 **응답 품질 한계**를 정리한다. 인프라(DB·RAG 파이프라인·세션 저장·웹뷰)는 정상 동작하며, 아래는 **LLM 응답 내용**의 문제다.

---

## 1. 채굴/제작 티어·레시피 환각 → **다음 이슈로 이관**

### 증상
모델이 "어떤 곡괭이로 어떤 광물을 캐는지", "무엇으로 무엇을 만드는지"를 **사실이 아닌 추측으로 생성**한다. RAG로 가져온 본문은 맞게 쓰면서도 요약·계획 줄에서 틀리는 **자기모순**이 잦다.

**재현 사례**
- **"철은 어떻게 캐?"** (5회 반복, temperature 0.2 → 5/5 동일):
  - 헤드라인: "철 광석을 캐려면 돌 곡괭이로는 안 되고 **철 곡괭이가 필요**" ❌ (정답: 돌 곡괭이)
  - 본문 단계: "**돌 곡괭이로** 철 광석 캐기" ✅
  - → 한 응답 안에서 모순. (철을 캐려면 철 곡괭이가 필요 = 순환 모순)
- **"양털 어떻게 구해?"**:
  - 가위 제작 경로를 "**돌 2개 채집 → 철 주괴 2개 제작**"으로 날조 ❌ (철 주괴는 돌이 아니라 철광석 제련물)
  - "**철 곡괭이로 돌 채집**" ❌ (돌은 나무 곡괭이부터 가능, 과잉·역순)
  - "**목탄으로 침대 제작**" ❌ (침대는 양털 3 + 판자 3, 목탄 무관)

### 정답 (ground truth)

**채굴 티어 — 광물별 최소 곡괭이**

| 광물 | 최소 곡괭이 |
| --- | --- |
| 돌·조약돌 | 나무 |
| 석탄·철·구리·청금석 | **돌** |
| 금·레드스톤·다이아몬드·에메랄드 | **철** |
| 흑요석·고대 잔해(네더라이트) | 다이아 |

> 나무·금 곡괭이로는 철 이상을 캐도 아이템이 드롭되지 않는다.

**헷갈리기 쉬운 레시피**

| 결과물 | 재료 |
| --- | --- |
| 철 주괴 | 철광석(또는 철 원석)을 **화로에 제련** (돌로 만들 수 없음) |
| 가위 | 철 주괴 2개 |
| 침대 | 양털 3 + 판자 3 (같은 색 양털, 목탄 무관) |

### 원인
위키 청크에 "광물 → 최소 곡괭이 티어", "재료 → 결과물" 관계가 **구조화된 사실로 들어있지 않다.** 그래서 LLM이 요약·계획 단계에서 추측으로 메우고, RAG는 ground truth를 *강제*하지 못한다. 검색 top-k(3→5)·온도(0.3→0.2) 튜닝은 오답의 '종류'만 바꿨을 뿐 근본 해결이 아니다.

### 해결 방향 (다음 이슈)
- **structured_db**: MySQL에 (a) **채굴 티어 표** (b) **제작 레시피 표**를 두고, `structured_db_retriever` 노드가 사실을 결정적으로 주입.
- 또는 **11노드 Agentic Workflow**의 `plan_verifier`(+`alternative_planner`) 노드로 생성된 계획의 실현 가능성·티어를 검증.
- (임시 완화책, 미적용) 시스템 프롬프트에 위 티어·레시피 표를 하드코딩 — 가볍지만 근본책은 아님.

### 영향 범위
**콘텐츠 품질에 한정.** #5의 DB 인프라(MySQL/Qdrant Cloud)·RAG 검색·세션/메시지 저장·검증용 웹뷰는 정상 동작한다.
